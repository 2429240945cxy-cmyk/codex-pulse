# 指标口径

## 统计对象

| 对象 | 定义 |
| --- | --- |
| 模型请求 | 一次模型调用，以 response ID 去重。旧格式没有 ID 时使用确定性标识。 |
| 对话轮次 | 一次用户输入触发的运行，可能包含多次模型调用和工具执行。 |
| 累计消耗 | 已收录模型请求的输入和输出之和，不重复叠加对话轮次。 |
| 账户额度 | Codex 日志返回的账户用量百分比、窗口和重置时间。 |

## Token

输入 token 已包含缓存输入。输出 token 已包含推理 token。

```text
token 总量 = 输入总量 + 输出总量
```

因此，缓存和推理是分项，不能再加到总量上。首版采集器尝试索引最近 90 天内更新且仍存在的会话文件；已进入本地数据库的记录会保留。

## 延迟和速率

- 对话首字延迟采用原生 `task_complete.time_to_first_token_ms`，包含本轮启动和等待。
- 请求首项延迟从请求发起算到首个输出项。输出项可能是推理或工具调用，不等同于首字。
- 对话总耗时包含工具执行。
- 请求耗时从日志中的请求开始算到最后输出项完成，排除其后的工具执行。
- 行内 TPS 为输出 token 除以对应对象的总耗时。
- 概览 TPS 使用有计时记录的模型请求加权计算，即输出总量除以请求耗时总量。
- P50 和 P95 取筛选结果中最近最多 1,000 个已完成对象的有效样本。

首次输出、请求开始时间或完整日志缺失时，相关值为空。

## 费用估算

```text
费用 = 未缓存输入 × 输入单价
     + 缓存输入 × 缓存输入单价
     + 缓存写入 × 缓存写入单价
     + 输出 × 输出单价
```

单价单位为美元每百万 token。模型请求按自己的上下文长度计价，再汇总到对话轮次；不会用一轮累计输入长度判断长上下文。

速度档位由页面中的估价选项选择，默认 Standard。它是估算参数，不代表采集端识别到了实际服务速度。

API 等价费用和 Codex Standard credits 使用不同的官方价目表。订阅内含额度的消耗规则不能直接用公开 credits 单价替代。项目不从整数百分比推断固定的每周 token 配额。

当前估算不覆盖工具独立费用、地区加价、未记录的 12 小时缓存溢价。价格更新失败时沿用最近有效表；历史记录使用当前价格重算，不代表历史扣款。

## 数据来源

采集端只读 Codex 的本地会话文件和 SQLite 日志。`token_usage_record` 与兼容的 `token_count` 事件会去重处理。日志不是稳定的公开接口，应用升级后可能需要适配。
